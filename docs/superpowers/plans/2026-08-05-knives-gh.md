# knives gh Implementation Plan (PR 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `knives gh -- <args...>` absorbs the fork-shaped brain of the `gh` shell shim — target-repo resolution, GitHub-App token export, and jj detached-HEAD compensation — so the shim shrinks to a thin exec wrapper. Agents keep typing `gh`; nothing about the interception is visible to them. Closes #8.

**Spec:** `docs/superpowers/specs/2026-08-05-release-correctness-and-knives-gh-design.md` (section "PR 2") — read it first. The reference implementation being ported is `~/.dotfiles/shims/gh` (457 lines of bash, readable, heavily commented); every behavior below cites its line numbers.

**Architecture:** One new module `src/commands/gh.rs` with a pure core (URL normalization, spec parsing, API-owner extraction, pr-subcommand parsing, argument injection — all unit-testable without processes) and a thin effectful shell (git-config reads, `gh-app-token` invocation, git-wrapper tempdir, spawn of the real gh). The pipeline, in shim order: mint a token if `GH_TOKEN` is unset (shim lines 181-204) → if in a jj repo and this is a `gh pr` call, compensate for detached HEAD (lines 406-452) → run the real gh and exit with its code. The routing table stays in git's own config; knives reads, never owns.

**Tech Stack:** Rust edition 2024, clap (already a dependency). No new crates: the GraphQL owner scan is a hand-rolled scanner, not a regex dependency.

## Global Constraints

- **jj, not git** for this repo's own VCS. One commit per PR, described at the end (Task 8). Where a step says "commit", skip it.
- **Gates:** `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features --workspace -- -D warnings`, `cargo nextest run --all-targets --all-features --workspace`, `bun run lint`, `bun run typecheck`, `bun run test:knives-plugin`.
- **Identity guard (load-bearing here):** `tests/no_hardcoded_identity.rs` forbids the default forge host written with a trailing slash as one literal in `src/`, `docs/`, `plugin/`, `skills/`, `hooks/`. The bare host without the slash is allowed (src/forge.rs:212 uses it). Rule for this PR: define ONE constant in `src/commands/gh.rs`:

  ```rust
  /// The default forge host. Assembled where a slash must follow so the
  /// no-hardcoded-identity scan (which needles on the host plus slash) stays
  /// meaningful about remote URLs elsewhere.
  const DEFAULT_HOST: &str = "github.com";
  ```

  and build every URL/config key via `format!` interpolation (`format!("https://{DEFAULT_HOST}/{spec}")`), never as one literal.
- **Exit-code fidelity:** `knives gh` exits with the real gh's exit code, streams its stdio untouched, and adds NOTHING to stdout/stderr on the happy path. It is plumbing; any knives-side chatter would corrupt `gh ... --json` consumers.
- **House style:** doc comments state behavior + motivating failure; test names are sentences; Given/When/Then in tests; `#![allow(clippy::indexing_slicing, reason = ...)]` in test modules.
- **The Python credential helper is out of scope.** `gh-app-token` stays exactly as it is; knives invokes it over the credential-helper protocol like the shim does. No Rust JWT, no token caching in knives.

```rust
pub(crate) fn normalize_url(url: &str) -> Option<String> {
    if url.is_empty() {
        return None;
    }
    let mut url = url.to_owned();
    // SSH scp-form git@host:owner/repo -> https://host/owner/repo
    if let Some(rest) = url.strip_prefix("git@")
        && let Some((host, path)) = rest.split_once(':')
    {
        url = format!("https://{host}/{path}");
    }
    if let Some(rest) = url.strip_prefix("ssh://git@") {
        url = format!("https://{rest}");
    }
    if !url.ends_with(".git") {
        url.push_str(".git");
    }
    Some(url)
}

pub(crate) fn url_from_spec(spec: &str) -> Option<String> {
    if spec.is_empty() {
        return None;
    }
    if spec.contains("://") {
        return normalize_url(spec);
    }
    let slashes = spec.matches('/').count();
    if slashes >= 2 {
        normalize_url(&format!("https://{spec}"))
    } else {
        normalize_url(&format!("https://{DEFAULT_HOST}/{spec}"))
    }
}

pub(crate) fn credential_path(url: &str) -> Option<&str> {
    let rest = url.strip_prefix("https://")?;
    let (_, path) = rest.split_once('/')?;
    Some(path)
}
```

```rust
/// The owner a `gh api` invocation targets, or None when it carries no signal.
///
/// These invocations often run outside the target repo's checkout and carry no
/// -R, so remote-based resolution would route the token to the wrong owner —
/// that is the failure this exists for (shim lines 80-86). Pure node-id
/// GraphQL mutations genuinely have no signal; `gh-app-token` honors
/// GH_APP_OWNER for those, which is out of knives' hands.
pub(crate) fn owner_from_api_args(args: &[String]) -> Option<String> {
    for argument in args.iter().skip(1) {
        if argument.starts_with('-') {
            continue;
        }
        let bare = argument.strip_prefix('/').unwrap_or(argument);
        for prefix in ["repos/", "orgs/", "users/"] {
            if let Some(rest) = bare.strip_prefix(prefix) {
                let owner = rest.split('/').next().unwrap_or("");
                let owner = owner.split('?').next().unwrap_or("");
                if !owner.is_empty() && !owner.contains('{') {
                    return Some(owner.to_owned());
                }
                return None;
            }
        }
    }
    let joined = args.join(" ");
    // Oracle amendment: LEFTMOST match wins across BOTH patterns — the shim's
    // single alternation regex returns the first match in the text, so a query
    // naming organization(login:"a") before repository(owner:"b") routes to "a".
    // Checking one keyword fully before the other would invert that.
    let candidates = [("repository", "owner"), ("organization", "login")]
        .into_iter()
        .filter_map(|(keyword, field)| {
            graphql_field(&joined, keyword, field)
                .map(|(offset, owner)| (offset, owner))
        })
        .min_by_key(|(offset, _)| *offset);
    if let Some((_, owner)) = candidates {
        return Some(owner);
    }
    None
}

/// First `keyword ( ... field : "value" ... )` in the text, quote-agnostic,
/// returned with the byte offset of the match so callers can pick the leftmost
/// across several keywords (shim parity: one regex, first match wins).
fn graphql_field(text: &str, keyword: &str, field: &str) -> Option<(usize, String)> {
    let mut search = text;
    let mut consumed = 0usize; // byte offset of `search` within `text`
    while let Some(at) = search.find(keyword) {
        let match_offset = consumed + at;
        let after = &search[at + keyword.len()..];
        let after_ws = after.trim_start();
        if let Some(body) = after_ws.strip_prefix('(') {
            // The field must come FIRST inside the parens, exactly like the
            // shim's regex (line 113: `\([[:space:]]*owner[[:space:]]*:`).
            // Scanning for the field ANYWHERE inside the parens routed
            // `repository(name:"x", owner:"a") … organization(login:"b")` to
            // "a" while the shim routes to "b" — a wrong-owner token mint,
            // caught in review with a reproduced parity matrix.
            if let Some(rest) = body.trim_start().strip_prefix(field) {
                let rest = rest.trim_start();
                if let Some(rest) = rest.strip_prefix(':') {
                    let rest = rest.trim_start();
                    if let Some(quote) = rest.chars().next().filter(|c| matches!(c, '"' | '\'')) {
                        let value: String = rest
                            .chars()
                            .skip(1)
                            .take_while(|c| *c != quote)
                            .collect();
                        if !value.is_empty()
                            && value
                                .chars()
                                .all(|c| c.is_ascii_alphanumeric() || matches!(c, '.' | '_' | '-'))
                        {
                            return Some((match_offset, value));
                        }
                    }
                }
            }
        }
        consumed += at + keyword.len();
        search = &search[at + keyword.len()..];
    }
    None
}
```

0. `gh api` owner signal → `url_from_spec("{owner}/gh-api")` (placeholder repo segment; only the owner matters for routing — shim lines 123-135).
1. `-R`/`--repo`/`--repo=`/`-R=` → `url_from_spec` (lines 137-150). Terminal when the flag is present, even with an empty value.
2. `git config --get-regexp '^remote\..*\.gh-resolved$'`, first line: value `base` → that remote's URL; any other value → `url_from_spec(value)` (lines 151-164). Terminal whether or not resolution succeeds.

```rust
/// The token gh should run with, or None to leave gh on the user's own auth.
///
/// Reads git's OWN credential config — the routing table stays in
/// gh-app-routes.gitconfig, single source of truth for git and knives alike —
/// and speaks the credential-helper protocol to gh-app-token, which does the
/// per-owner routing internally from the `path` line (shim lines 181-204).
/// Any failure (no helper configured, helper errors, no password line) is
/// None: falling back to user auth is the shim's contract, not an error.
pub(crate) fn mint_token(target_url: &str) -> Option<String>
```

Mechanics, byte-compatible with the shim:
1. `git config --get-all credential.https://{DEFAULT_HOST}/.helper` (key built by interpolation; see Global Constraints). Note `--get-all`: git reports only the final helper for `--get-urlmatch`, and the route is a chain ending in the user fallback, so the app helper is picked out of the chain directly (shim lines 184-188).
2. First line starting `!gh-app-token ` → profile is the remainder.
3. Spawn `gh-app-token <profile> get`, write `protocol=https\nhost={DEFAULT_HOST}\npath={path}\n\n` to stdin where `path = credential_path(target_url)`, read stdout, take the first `password=` line's value.

The caller (Task 6) applies it only when `GH_TOKEN` is not already set in the environment.

Behavior of `run` (composition, shim order):

1. Mint: if `std::env::var_os("GH_TOKEN")` is none and `resolve_target_url(args, &cwd)` yields a URL and `mint_token` yields a token → the child gets `GH_TOKEN` set (pass via `.env()` on the spawned command, never `set_var` in-process).
2. Not a jj repo (`jj root` fails, shim 220-222) or no `pr` subcommand → spawn real gh with the args untouched, wait, `std::process::exit(child_status_code)`.
3. `pr` subcommand: get `current_bookmark` (empty → placeholder `__jj_detached__` for the wrapper, same as shim line 255). Injection per the shim's table:
   - `create`: `--head` present → run as-is; no bookmark → die with the shim's exact no-bookmark message (lines 240-249, to stderr, exit 1); else append `--head <bookmark>`.
   - `view|checks|diff|merge|checkout|edit|comment|ready|review|update-branch`: positional target present → as-is; no bookmark → die; else `inject_positional`.
   - anything else: as-is.
4. Always under the git wrapper when in a jj repo (even with explicit targets — gh checks the current branch internally, shim line 434): create a tempdir, write the wrapper script (the shim's heredoc, lines 261-296, copied VERBATIM into a Rust raw string — it is bash, executed as bash, and already field-proven), `chmod 0o755`, spawn real gh with `PATH={wrapper_dir}:{PATH}`, `_JJ_BOOKMARK={bookmark}`, `_JJ_WRAPPER_DIR={wrapper_dir}`, wait, remove the tempdir (`tempfile::TempDir` does it on drop), exit with the child's code.

Spawn-and-wait, not `exec`: the wrapper tempdir must be cleaned up after gh exits, which `exec` makes impossible (the shim has the same structure: run, rm -rf, exit — lines 299-303). On a child killed by a signal (`code()` is None), exit 1.

**Child stdio inheritance is explicit (oracle amendment, P1):** launch the real gh with `.stdin(Stdio::inherit()).stdout(Stdio::inherit()).stderr(Stdio::inherit()).status()` — NEVER `.output()`. Capturing would break interactive gh (`pr create` opening $EDITOR, prompts, pagers) and buffer streaming JSON; the shim's exec semantics mean gh owns the tty today and must keep owning it. Test code may `.output()` on the OUTER `knives` process; the inner gh child inherits.

The shim-marker rule for `real_gh`: a candidate `gh` on PATH whose first 512 bytes contain `knives-gh-shim` is the shim and is skipped. Task 9's rewritten shim carries that marker in a comment. `KNIVES_REAL_GH` (which the shim exports, having already computed the real path its own way) short-circuits the scan and is the normal path in production.
